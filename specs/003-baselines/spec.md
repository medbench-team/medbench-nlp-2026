# Feature Specification: Бейзлайны — Naive и TF-IDF/CRF, воспроизведение статьи

**Feature Branch**: `003-baselines`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "Переходи к следующей спеке" — спека 003 `baselines` из
`docs/ROADMAP.md`: «Naive + TF-IDF (char 3–8) + LogReg: воспроизведение цифр статьи,
проверка пайплайна».

## Контекст

- В статье RuMedBench два простейших бейзлайна: **Naive** (самый частый класс) и
  **TF-IDF + LogReg / CRF**. Их официальная реализация (`code/linear_models`, коммит `dd57f4f`)
  прочитана: символьные n-граммы длины 3–8, логистическая регрессия «один против всех» с C=10;
  для пар текстов (NLI, DaNet) тексты склеиваются через пробел; для NER — CRF на признаках
  слова и соседей (c1 = 0.1, c2 = 0.01, 200 итераций, сид 128).
- Опубликованные цифры (open test, %): Naive — Top3 10.58/22.02, SymptomRec 1.93/5.30, DaNet 50.00,
  NLI 33.33, NER 93.66/51.96, Overall 35.21; TF-IDF — 49.76/72.75, 32.05/49.40, 51.95, 59.70,
  94.40/62.89, Overall 58.46.
- Спеки 001 (роли данных) и 002 (метрики, реестр прогонов, сводка, сабмит) реализованы. Это
  первая спека, которая прогоняет полный цикл «обучение → предсказание → сохранение прогона →
  сводка → сабмит».
- Официальные модели обучались на train, где есть несколько дубликатов test (ADR-014: RuMedNER
  28 строк, RuMedSymptomRec 1). Наша роль «обучение» их исключает, поэтому для этих двух задач
  возможны небольшие расхождения с опубликованными цифрами.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Воспроизвести бейзлайны статьи на финальном тесте (Priority: P1)

Участник одной командой обучает Naive и TF-IDF/CRF на роли «обучение» для пяти задач статьи,
делает один финальный прогон на роли «финальная оценка», сохраняет результаты как прогоны и
видит их в сводной таблице рядом с опубликованными цифрами.

**Why this priority**: доказывает, что весь пайплайн (данные → подход → оценка → сводка)
работает и даёт сравнимые с публикацией числа; без этого нельзя доверять будущему SotA.

**Independent Test**: запустить бейзлайны и сравнить их строки в сводке с опубликованными
Naive и TF-IDF — расхождение в пределах допуска.

**Acceptance Scenarios**:

1. **Given** данные и харнесс, **When** участник запускает бейзлайн Naive, **Then** для всех
   пяти задач сохранены финальные прогоны, метрики совпадают с опубликованными Naive
   (≤ 0.01 п.п. для NLI, DaNet, Top3, SymptomRec; NER — сравнение с объяснением расхождения).
2. **Given** данные и харнесс, **When** участник запускает бейзлайн TF-IDF/CRF, **Then** для всех
   пяти задач сохранены финальные прогоны, метрики отличаются от опубликованных не более чем на
   1 п.п. по каждой метрике, Overall — не более чем на 1 п.п.
3. **Given** финальные прогоны уже есть, **When** участник повторно запускает бейзлайн без
   обоснования, **Then** финальные прогоны не перезаписываются (правило одного финального
   прогона), а участник видит, как запустить только прогон на «подборе».
4. **Given** сохранённые прогоны, **When** строится сводка, **Then** в ней есть строки Naive и
   TF-IDF с Overall и разницей с лучшим опубликованным результатом.

---

### User Story 2 - Метрики на «подборе» для разработки (Priority: P1)

Участник получает метрики бейзлайнов на роли «подбор» (открытый dev) как ориентир для
сравнения будущих подходов (LLM, энкодеры) без обращения к финальному тесту.

**Why this priority**: спеки 004–007 сравнивают свои варианты на «подборе»; бейзлайн —
нижняя планка там же.

**Independent Test**: запустить бейзлайны только на «подборе» и увидеть их в таблице
«разработка» сводки; финальный тест при этом не используется.

**Acceptance Scenarios**:

1. **Given** данные, **When** участник запускает бейзлайны в режиме «только подбор», **Then**
   сохраняются прогоны на роли «подбор», финальных прогонов не появляется.
2. **Given** прогоны на «подборе», **When** строится сводка, **Then** они в таблице
   «разработка», отдельно от финальной.

---

### User Story 3 - Первый сабмит на medbench.ru (Priority: P2)

Участник получает предсказания бейзлайнов для закрытого теста сайта (RuMedDaNet, RuMedNLI —
TF-IDF; RuMedTest — наивный ответ, т.к. обучающих данных нет) и собирает архив для загрузки.

**Why this priority**: проверка всего контура сабмита до появления сильных моделей; даёт точку
отсчёта на закрытом лидерборде.

**Independent Test**: собрать архив сабмита из прогонов бейзлайна и проверить его формат
командой сборки сабмита.

**Acceptance Scenarios**:

1. **Given** обученный TF-IDF, **When** участник запускает предсказание для закрытого теста,
   **Then** сохраняются прогоны роли «сабмит» для DaNet и NLI и наивный — для RuMedTest.
2. **Given** эти прогоны, **When** собирается сабмит, **Then** архив содержит три файла в
   формате сайта, без предупреждений.

### Edge Cases

- Модель предсказывает для Top3/SymptomRec меньше трёх различных кодов (классов в train меньше
  трёх не бывает, но вероятности могут совпадать) → тройка всегда состоит из трёх различных
  меток в порядке убывания уверенности.
- Метка теста отсутствует в train (Top3: 104 кода в test, 105 в train; SymptomRec — 129 vs 141)
  → такие примеры просто не угадываются, без ошибки.
- Нехватка памяти на сервере (≈ 3 ГБ RAM) при символьных n-граммах 3–8 на 11 тыс. пар NLI →
  обучение укладывается в доступную память; если нет — понятная ошибка и рекомендация запуска
  на машине с большим объёмом памяти.
- Повторный запуск: обученная модель не сохраняется между запусками (бейзлайн обучается за
  минуты); воспроизводимость обеспечивается фиксированным сидом и конфигом.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST реализовать бейзлайн Naive так же, как в официальных предсказаниях:
  NLI — всегда `entailment`, DaNet — всегда `да` (при равенстве классов — первая метка в
  порядке частоты, как в официальных файлах); Top3/SymptomRec — три самых частых кода
  обучающей выборки; NER — самый частый тег каждого токена в обучающей выборке (`O` для
  незнакомых); RuMedTest (сабмит) — первый вариант ответа, как в образце сайта.
- **FR-002**: Система MUST реализовать бейзлайн TF-IDF/CRF с гиперпараметрами официальной
  реализации (символьные n-граммы 3–8, LogReg C=10 «один против всех»; CRF c1=0.1, c2=0.01,
  200 итераций, сид 128; склейка пар текстов через пробел).
- **FR-003**: Бейзлайны MUST обучаться только на роли «обучение», а результаты сохраняться
  только через реестр прогонов спеки 002 с полным описанием конфигурации.
- **FR-004**: Запуск MUST поддерживать выбор задач и ролей: «подбор», «финальная оценка»,
  «сабмит»; по умолчанию — «подбор».
- **FR-005**: Финальный прогон MUST подчиняться правилу «один финальный прогон на
  конфигурацию» (без обхода).
- **FR-006**: Результаты бейзлайнов MUST быть сопоставлены с опубликованными цифрами в отчёте
  о воспроизведении: таблица «наше / статья / разница» и объяснение расхождений (ADR-014,
  версии библиотек).
- **FR-007**: Весь прогон бейзлайнов на пяти задачах MUST выполняться одной командой на сервере
  проекта без GPU.

### Key Entities

- **Бейзлайн (Baseline)**: подход `naive` или `tfidf` с фиксированными параметрами; обучается
  на роли «обучение» задачи.
- **Прогон бейзлайна**: результат на роли «подбор» / «финальная оценка» / «сабмит», сохранённый
  через реестр спеки 002.
- **Отчёт о воспроизведении**: таблица сравнения с опубликованными Naive и TF-IDF.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Naive совпадает с опубликованными цифрами ≤ 0.01 п.п. по NLI, DaNet, Top3,
  SymptomRec. Для NER официальная стратегия Naive не опубликована (кода нет, есть только
  предсказания); используется «самый частый тег токена в обучающей выборке», расхождение с
  опубликованными 93.66 / 51.96 отражается в отчёте о воспроизведении (research.md R2).
- **SC-002**: TF-IDF/CRF отличается от опубликованных цифр не более чем на 1 п.п. по каждой
  метрике каждой задачи и по Overall.
- **SC-003**: Полный прогон обоих бейзлайнов (обучение + подбор + финальная оценка + сабмит)
  на сервере проекта занимает менее 30 минут.
- **SC-004**: В сводной таблице появляются финальные строки Naive и TF-IDF с Overall по пяти
  задачам.
- **SC-005**: Архив сабмита из прогонов бейзлайна собирается без предупреждений.

## Assumptions

- Обучение — на роли «обучение» (без дубликатов test, ADR-014), а не на сыром train: это
  честнее и согласуется с принципом I; расхождения для NER/SymptomRec документируются.
  Точное побитовое повторение официальных предсказаний не требуется — версии библиотек и
  решатели отличаются.
- Подбор гиперпараметров бейзлайнов не выполняется: берутся параметры статьи (это
  воспроизведение, а не улучшение).
- RuMedTest не имеет обучающих данных, поэтому TF-IDF для него не строится; для сабмита
  используется наивный ответ.
- Обученные модели не сохраняются как артефакты (обучение занимает минуты).
